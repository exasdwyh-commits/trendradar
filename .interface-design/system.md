# TrendRadar 写作台界面规范

## 使用目标

日常以公众号母稿为主，再改编多平台内容。工作台负责恢复进度和选择下一步，编辑器负责持续写作。风格保持安静、紧凑、清晰，复用现有浅色与深色主题。

## 信息架构

核心导航：工作台、选题简报、稿件、素材库、发布中心。扩展工具与系统默认收起，记住用户展开偏好。

编辑器提供独立「创作 Agent」面板：任务设置、已保存进度、大纲确认、候选正文和审稿、平台版本、最终采用。输入变化需重新规划。生成期间显示暂停请求状态，不把候选稿直接替换正文。

工作台先呈现最近的未完成稿件，再呈现待发与最近稿件；辅助区域放三个选题候选和快捷素材记录。数量来自完整数据库统计，列表采用有限摘要，不加载正文与版本历史。

## 视觉约定

- 使用 `frontend/src/styles.css` 中的主题变量：`--bg`、`--bg-elev`、`--fg`、`--fg-muted`、`--border`、`--accent`、`--radius`。
- 按钮、图标、状态、加载和错误提示复用已有组件；实心强调按钮优先用于新建母稿与继续写作。
- 工作台桌面两列比例约 1.65:1，列间距 24px。续写卡片顶部细强调边线；稿件采用紧凑列表，避免一稿一卡。
- 主标题保持既有字号；续写标题 24px，小屏 21px；说明与元信息使用 13px 与 11–12px。
- 演示、真实、混合的数据标识必须保留；来源和日期靠近选题，不把历史简报称为今日数据。

## 交互与响应式

- 新建或延伸创作必须防止重复提交；失败时显示错误并允许重试。
- 页面切换取消旧请求，保留导航；懒加载失败提供重新加载入口。
- 1100px 以下工作台单列，600px 以下创作流程两列；960px 以下导航横排，编辑器工具栏换行、正文与右侧面板纵向排列。
- 桌面编辑器自动收起导航，保留正文空间；布局变化应验证 1280px 桌面与 390px 小屏。
- 重要标题与输入有可访问名称；稿件通过真实链接打开，支持键盘操作。
