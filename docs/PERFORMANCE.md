# 性能与稳定性优化（2026-10-02）

本次改动覆盖页面加载、页面读取请求生命周期和写作台查询索引。

## 前端

所有页面通过 React `lazy` 按路由加载，侧栏保持可用。加载期间显示状态和骨架；页面下载或渲染失败时显示重新加载入口，仍可从侧栏进入其他页面。

同一工作区、相同依赖的 Vite 生产构建对比：

| 指标 | 改动前 | 改动后 |
|---|---:|---:|
| 入口 JavaScript | 484.21 kB | 356.43 kB |
| 入口 JavaScript（gzip） | 151.30 kB | 116.82 kB |
| 编辑器独立脚本 | 包含在入口中 | 48.45 kB（gzip 15.76 kB） |

入口脚本减少约 26.4%。进入某个页面时仍需加载该页面及其共享依赖；以上是构建产物大小，不代表首屏总下载量或浏览器实测加载时间。

`useFetch` 在路径变化、重新请求和卸载时取消旧 GET 请求，并保留响应过期保护。切换资源时清理旧数据；刷新同一资源时保留已有数据；重试时清理旧错误；禁用请求时重置加载状态。

## 数据库

新增迁移 `0007_studio_query_indexes.sql`：

- `document_materials(material_id, document_id)`：加速素材引用数及关联稿件查询。
- `publications(document_id, published_at DESC)`：加速稿件发布数、发布矩阵和按时间排序的发布历史。

旧查询按每个列表条目扫描关联表；新查询按索引查找，单稿件发布历史也无需临时排序。迁移仅新增索引，启动服务时自动执行。测试覆盖 v2/v6 数据库升级、已有内容保留、外键完整性和重复迁移。

离线合成数据基准：5,000 篇稿件、5,000 条素材、50,000 条绑定、25,000 条发布记录。使用内存 SQLite，查询预热后执行 5 次，取中位数，并比较迁移前后的完整返回值。

| 查询 | 改动前 | 改动后 |
|---|---:|---:|
| 素材列表（200 条） | 298.349 ms | 1.033 ms |
| 稿件列表（200 条） | 154.316 ms | 0.800 ms |
| 发布中心（100 篇稿件、100 条记录） | 83.486 ms | 7.019 ms |

结果完全一致。这是本机合成数据上的数据库与序列化耗时，不包含 HTTP、磁盘或浏览器耗时；真实数据分布与设备会影响结果。新索引会增加少量存储及关联写入开销。

在已安装后端依赖的环境中，从项目根目录复现：

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_studio.py --size 5000 --repeat 5
```

基准只操作独立内存数据库，不读取应用数据库或调用外部服务。
