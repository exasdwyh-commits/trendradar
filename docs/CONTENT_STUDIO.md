# Content Studio 3.1

## 目标

把“AI 生成一篇文章”升级成“作者与 AI 共创一份可长期维护的内容资产”。

## 母稿原则

母稿只保存一个核心判断。平台版本不能自行增加新的事实或新的结论。

母稿可以来自：

1. 系统选题 → Research → Thesis → Writer；
2. 长期趋势；
3. 用户空白新建。

## 编辑器

TipTap 负责结构化富文本。当前保留：

- H2 / H3
- 粗体 / 斜体
- 有序 / 无序列表
- 引用
- 链接
- Undo / Redo
- 自动保存
- 手动版本

数据库同时保存：

- TipTap JSON
- HTML
- plain text

这样后续既能继续编辑，也能做平台适配、全文搜索和导出。

## 版本历史

每次保存形成新的 `document_versions`：

- AI_DRAFT
- MANUAL
- AI_EDIT
- IMPORT
- RESTORE

恢复历史版本本身也生成一个新的版本，不覆盖历史。

## 证据侧栏

绑定系统研究选题的母稿会自动展示底层 Intelligence。

目标不是把来源堆满屏幕，而是在写作过程中能快速判断：

- 这是 PRIMARY 还是 VERIFIER？
- 这是 FACT / CLAIM / INFER？
- 原文在哪里？

下一阶段可进一步做到“选中一句 → 这句话依据是什么？”

## 配图导演

`media_assets` 当前保存的是**视觉策划**，不是自动堆 AI 图。

优先级：

1. 真实数据图
2. 商业机制 / 产业链图
3. 真实照片 / 截图
4. AI 插画

每篇默认只建议 2–5 张，包括：

- 放置位置
- 图类型
- 为什么需要
- 图的内容
- 比例
- 如适合 AI 生成，则提供 prompt

## 平台版本

母稿通过 `platform_variants` 产生：

- WECHAT
- XIAOHONGSHU
- ZHIHU
- TOUTIAO
- X

不是简单裁字数，而是按平台重新组织表达。

## 发布

3.1 的发布中心先做三件可靠的事：

1. 平台版本生成
2. 平台格式导出
3. 已发布状态 / URL 记录

不在没有真实平台 API 授权的情况下伪装“一键直发”。

后续当某个平台具备稳定官方 API / Connector / 登录授权时，再通过 Publisher Adapter 接入。

## 下一阶段候选

实际使用后再决定优先级，不提前堆功能：

- 选中文本 AI 操作
- 段落级 evidence link
- 图片生成 / 图表生成
- 封面工作流
- 微信编辑器样式模板
- 平台直发
- 定时发布
- 发布指标自动回流
- 内容素材库
